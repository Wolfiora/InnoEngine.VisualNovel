# 自定义节点编译

`Compiler/Extensions` 提供纯编译扩展，不在玩家程序中增加另一套解释器。它适合将专用创作节点转成普通对白、变量、条件、舞台或 C# 命令指令。

显式建立当前编译所有者的 `StoryCompilerRegistry`，注册 `StoryNodeCompiler` 工厂，再传给 `StoryCompiler` 的第二个参数。注册表属于当前编辑器代际，不应存入静态字段。相同 ID 和保留的 `inno.vn.*` ID 会立即拒绝；`Clear()` 释放工厂，已经产生的程序仍只含中立内置数据。

扩展继承引擎 `GraphNodeDefinition` 的名称、分类和端口契约，实现 `Lower(StoryNodeCompilationContext)`。使用 `Read<T>()` 原生读取独立设置，使用 `Create(builtInId, settings)` 生成内置节点。上下文的变量声明也是独立副本。不得访问文件、资产数据库或执行运行副作用。

降级前后必须保持节点 ID，以及端口 ID、方向、类型、容量和必需标记。显示名称可以不同。分支节点可降为拥有同样动态输出的条件、选项或命令；需要定制运行行为时，降为 `CommandNode` 并按命令协议提供正常运行脚本。降级不能产生另一个自定义 opcode，也不能隐式重连图。复杂多节点扩展应由普通 Authoring 图事务显式生成。

生产编译器会再次校验表达式、变量、目标、资源指令及并行组。异常定位到原章节/节点；失败不返回部分程序、不写回源图。缺失工厂保留原始中立数据，恢复注册后可以重新编译。存档、等待与调试继续使用内置运行链和原源码身份。

当前正式引擎 API 未导出类型发现目录，也没有让 `AssetImportContext` 取得编辑器注册 owner 的协议。因此默认导入器和节点菜单**没有自动接入该注册表**。这份显式编译 API 不代表自定义节点已获得完整无代码创作、保存和发布工作流；不可用静态全局表、扫描 DLL 或修改引擎替代该缺口。正常玩法扩展目前优先使用已接通的 C# 命令目录。
