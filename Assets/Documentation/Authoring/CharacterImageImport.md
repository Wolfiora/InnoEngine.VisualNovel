# 批量匹配角色差分图像

在“VN 角色设计”打开角色，先为姿势和部位设置可读名称，再展开“批量差分图像匹配与预览”。无需编写脚本。

把已经准备好的图片放入当前工程 `Assets` 内的普通文件夹，使用以下文件名：

```text
pose__挥手__身体.png
pose__自然站立__身体.png
expression__微笑__脸.png
expression__惊讶__眼睛.png
```

`pose` 替换某姿势的部位基础图像，`expression` 替换表情的共享部位覆盖。也可用稳定 ID 代替名称；ID 优先，名称必须唯一。名称匹配不区分大小写。字段之间用两个下划线分隔，因此名称中不要使用该分隔符。

1. 在 File Browser 完成 PNG/JPEG 的原生导入。
2. 输入图片文件夹相对 `Assets` 的路径，不填写 `Assets` 前缀。
3. 默认只匹配已有变体。需要新建时明确启用“允许创建命名姿势/表情”。新姿势复制当前默认姿势；新表情继承所有原值，仅覆盖匹配图像。
4. 默认保留部位尺寸、变换、遮罩、颜色、动画与其他表情覆盖。启用同步像素尺寸后，仅对应姿势部位的尺寸改用新图大小。
5. 点击准备，查看可用、缺失、重名、冲突和原生资源未就绪信息。
6. 可显示冻结的候选角色，在同一生产舞台预览中选择候选姿势/表情。这个候选尚未写入文档。
7. 点击“应用全部可用匹配”，一次提交审核中的可用项。它是一个原生 History 操作，可以整批 Undo/Redo，再保存角色源资产。

重复匹配同一变体/部位的条目全部视为冲突，不选择任意一个覆盖。无法匹配的条目保留在报告中，明确排除在可用子集外。若一个新姿势没有任何可用条目，不会留下空姿势。

表情的语义部位必须存在于所有姿势；先用角色设计器建立共享部位，再批量匹配图片。名称只影响显示和匹配，重命名不改变稳定 ID。

准备过程每次更新至多加载四张图片，可取消。只扫描所选文件夹的直接文件，每批最多 512 张图像、4096 个直接文件项；不递归扫描整个工程，不读取点前缀或 ~ 开头的目录，不跟随目录或文件链接。较大的图像仍可能需要等待引擎完成单次原生导入。

修改角色草稿会清除旧的准备/审核结果。提交还会再次验证原生属性摘要及所有相关图片的身份、路径和内容代际；其中任何一项变化，整批拒绝，原文档保留。候选显示副本不能作为提交数据，编辑器重载会释放临时审核，不保存 CLR 对象或另建资产索引。

当前逻辑测试覆盖真实 PNG 导入、匹配/冲突、变体创建、原生资产与依赖往返、旧审核拒绝和整批 Undo/Redo。正式编译状态见仓库实施记录；本批未进行 GUI、实际 GPU 画面或大批量性能验收。
