# 自动存档

在「VN 游戏设置」中可以开关「进入选项时自动存档」。游戏使用独立的 3 个轮换自动槽；它们不覆盖手动槽或快存槽。必须由宿主向 `NovelSceneSystem.ConfigurePersistence` 提供正式原生 codec 和原子存储，自动保存才会工作。当前选定引擎的 Runtime 根序列化入口仍有已记录的公开 API 缺口；没有 codec 的宿主不会把自动保存显示为可用能力。

进入一个新的选项边界时，会立即冻结变量、调用栈、阅读、NVL 页、舞台、音频及其他已经接通的快照域。即使当时正在读盘或刷新列表，后续写入使用的也是这份边界快照，不会捕获玩家已经推进到的下一句。

若连续出现多个待写边界，队列保留最新的一份，避免无界积压。已有 IO 完成后先选择空自动槽，满额后覆盖时间最早的一槽。IO 失败保留上一次有效数据，并在存档结果字段中显示原因。游戏已被重新开始、读档或回滚替换时，尚未开始写入的旧队列会被丢弃。

读档和回滚恢复到一个选项时不会立即再写自动存档；接下来真正进入新的选项边界才会请求。独立回想与无持久化服务的预览不运行此策略。

普通保存仍由 `SaveService` 负责完整数据包、构建指纹、候选恢复和原子写入。`SaveSnapshotAsync` 允许高级宿主写入已经捕获的边界，仍要求在会话所有者线程编码，再等待存储完成。此批次的故障验收使用可控存储替身，未进行实机磁盘故障测试。
