# 玩家设置与全局进度

“VN 游戏设置”可配置手动存档数量（1～10000，默认 100）和自动轮换数量（1～100，默认 3）；快存保留独立一个槽。内置组件把配置传给原生 SaveService。宿主尚无原生 codec 时操作禁用，但页面仍按项目容量显示；高级宿主显式提供的服务以其实际容量为准。

标题页“继续故事”在槽位检查完成后启用，选择最近的本构建兼容元数据存档，排除元数据已判定损坏、不兼容和空槽。载入仍执行全部快照验证；失败保留当前会话并显示错误，玩家可进入读档页选择其他槽。它不会迁移旧构建存档。三套页面和按钮动作都可以在设计器中编辑。

普通存档保存剧情位置、舞台、音频与历史；玩家设置、已读、收藏解锁及明确声明的 Global 变量分别进入原生全局数据包。回滚和读档不会撤销它们。

宿主提供 `GlobalProgressStore` 后，`NovelGameView` 使用同一套可编辑 UI 显示 `loading` 页面，在完成原生读取和候选验证之前不接受开始游戏等动作。新建游戏向导生成此页面；已有工程启用玩家数据前必须关联它。

读取失败时展示错误，允许重试。使用默认值需要两次明确操作，无法读取的旧数据在下一次有效写入前保留。不能静默清除解锁后自动覆盖。全局进度和设置都会验证通过后才应用，不会因另一份数据损坏而应用半个启动状态。

游戏运行后通过状态修订号检测全局变化，并检查玩家设置变化，自动合并一秒内的写入。全局数据与设置各自原子替换，存档槽不受影响。保存失败保留最后有效包，设置页提供重试入口，不会每帧重复写盘。停止 View 时先在 owner 上冻结最新原生字节，再释放序列化代际；迟到读取不会调用旧代 codec。

可绑定字段：`profile.ready`、`profile.loading`、`profile.failed`、`profile.error`、`profile.saving`、`profile.canUseDefaults`、`profile.confirmDefaults`。动作：`profile.retry`、`profile.defaults`、`profile.defaults.confirm`、`profile.defaults.cancel`。回想不创建玩家数据保存服务，不会写回主游戏进度。

Scene 宿主的 `ConfigurePersistence` 会同时关联普通存档与上述全局服务。**当前引擎尚未公开 Runtime 根序列化入口，因此未经宿主配置的发布游戏不能凭空拥有原生 codec。** 该接口缺口与玩家数据协调逻辑是两项独立状态，不能据此宣称发布游戏的存档已经全部可用。

本功能已通过正式脚本编译和逻辑测试，尚未实机验收；独立 Player 的原生 codec 接入仍受上述公开 API 缺口影响。
