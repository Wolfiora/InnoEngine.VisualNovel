# 语言图片、字体与缺字检查

在“VN 多语言”打开游戏已关联的原生翻译表。游戏语言和编辑器语言独立；普通读档保留玩家当前语言设置。

## 配置字体

在“字体与图片”选择语言，再在 File Browser 选择已导入的 TTF/OTF。

- “使用所选字体为本语言默认”替换该语言的普通 UI 默认字体；清除后继续使用主题/页面字体。
- “添加所选字体到回退链”按列表顺序补充缺字，可上移或移除，最多 16 个不重复字体。
- 命名富文本字体仍保留其用途；缺字时会依次尝试语言默认字体和回退链。
- 所有修改经过原生资源文档与 History，使用同一保存/撤销/重做。

字体选择以完整字素为单位，不切开组合字符或连接 emoji。选定同一字体的连续片段仍交给引擎 Text 塑形，保留片段内连字。Ruby 的正文与注音均使用回退链。没有任何字体覆盖时保留缺字并报告，不静默删除文字。

字体本身必须覆盖需要的字形；回退不会创造字体中不存在的字形。本文没有宣称完整双向混排或竖排支持。

## 配置语言图片

1. 选择原始图片，点击“将所选图片设为原图”。
2. 选择该语言的替换图片，点击“将所选图片关联为本语言版本”。
3. 保存翻译表，再重新启动正在使用旧内容的预览会话。

映射使用引擎资产身份，原图和替换图都是普通原生资源引用，导入器自动收集依赖。一个语言的一张原图只能有一个替换；替换只执行一次，不追踪映射链。

舞台、当前/先前转场画面、静态及绑定 UI 图片、头像与行内图标都会使用相同语言策略。舞台保留作者原来的构图范围；UI 按替换图的宽高适配，因此应检查不同语言画面。更换语言会重新建立页面并恢复合法焦点，旧按下/拖动的释放不能推进新页面。

源资产和角色/舞台声明不会被改写。活动会话冻结图片和字体声明；编辑资源后重启该会话。原生 UI 绘制快照记录实际图片及字体回退身份，依赖由游戏资源闭包恢复。

## 执行缺字检查

在“缺字检查”选择语言，在 File Browser 选择游戏，然后点击“检查所选游戏的静态文字”。检查使用当前翻译表草稿，以及游戏已保存、已编译的章节和页面；未保存的章节草稿不在此检查中。

检查按小批上下文推进，允许取消，已收集问题仍保留。范围覆盖页面自身、全部配置主题、台词、历史、姓名、选项、输入提示和收藏文案在实际控件中的字体上下文。同一字素的重复缺失按上下文合并，显示 Unicode 码点和次数。章节问题能定位共享节点；页面问题可打开对应资源。内置只读页面需要先创建项目副本再修改。

原生塑形不可用、默认字体未分配、命名字体缺失或内容错误会显示“检查失败”，与确实缺字分别统计。结果达到 10000 条时明确标记不完整。运行时变量、玩家输入和扩展动态文本无法静态证明覆盖；文字模板中的变量值不被假装替换为已检查的文字。修改内容、字体或重导入后应重新检查。

当前实现通过正式脚本编译、适配器行为与原生资源引用测试。尚未进行 GUI、实际字体后端/字形像素、GPU、显示缩放或实际上手验收；最新完整基线以实施状态为准。
