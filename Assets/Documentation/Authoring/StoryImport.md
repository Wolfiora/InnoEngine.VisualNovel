# 剧本导入与阅读稿

工作区「导入与阅读稿」支持 UTF-8 CSV、TSV 和约定纯文本。先打开目标章节；若需要匹配角色和配音，在资源浏览器选择游戏定义，再点击「匹配所选游戏角色与语音」。读取文件只读取外部文本，不改写原文件。

表格的语义列为 `text`、`speaker`、`characterId`、`voice`、`textId`、`note`、`layout`。只有台词列必需，其他列可以不分配；表头可自定义，再用列映射选择真实列。支持引号、双引号转义、单元格内换行及 UTF-8 BOM。布局填写 Adv、Nvl、Bubble、Overlay 或 Letter。

`speaker` 可以是字面姓名，也可以匹配游戏角色的显示名或别名。唯一匹配后使用稳定角色 ID，姓名继续参与游戏翻译。`characterId` 显式指定角色；有歧义时用这一列消除歧义。语音按提示资源 ID 或标题匹配，要求唯一、非循环的 Voice 提示，已分配录音。文本 ID 留空则生成新身份；显式 ID 不能与本章或同批记录重复。

纯文本用空行分隔台词，段内换行保留。短姓名后接半角或全角冒号表示发言人，例如 `澄：欢迎来到故事。`；无姓名的段落作为旁白。正文自身包含冒号时，可以在段首加一个冒号强制旁白，例如 `：https://example.com`，首个冒号不会进入台词。此格式按明确分隔约定解析，不智能推断演出、分支或脚本。

预览逐条列出角色、语音、布局、文本身份及错误。全部有效后，指定新片段名称和公开入口 ID，点击导入。导入生成普通入口、对白、结束和连线；不连接到现有流程，也不覆盖已有节点。可在图中接入，或选择该公开入口预览。整批使用一次原生 History，支持撤销、重做、保存、重开。预览后章节或匹配资源库发生改变时，必须重新审核。

单批最多一万句，预览文本预算 16 MiB。错误不会部分写入图；候选先经过同一个正式编译器。旁白、姓名和正文中的变量仍需在当前章节声明。

「导出当前章节阅读稿」将当前未保存草稿写入项目的 `artifacts/Exports/Reading-<文档ID>.txt`。每个节点列一次，保留对白、选项、语音和稳定跳转目标，循环不展开；变量保留作者占位符。阅读稿用于校对，原生图仍是控制流事实，不支持将任意阅读稿反向还原成自由图。

本批未进行 GUI 或实机操作验收。
