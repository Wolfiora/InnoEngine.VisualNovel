# 资源引用、重复与授权审计

“VN 资源审计”对比选定游戏的原生依赖闭包和当前项目 `Assets` 源文件。它使用引擎资产身份和序列化依赖；文件扫描与哈希只是临时分析，没有第二套资产数据库，也不会删除文件。

## 运行审计

1. 保存游戏和资源，在 File Browser 选择 `.ivnproject`。
2. 打开“VN 资源审计”，点击“审计所选游戏（保存内容）”。
3. 等待目录枚举与分块哈希，或点击“查看当前结果”。可以取消，已检查结果仍可查看。
4. 按路径查找，并筛选已引用、当前游戏未引用、字节重复、存在问题、无法判断或创作数据。
5. 选择结果可定位引擎资产；引用来源来自原生闭包中的直接父资产。

“查找剧情 / 控件位置”在小批量扫描冻结的编译指令和页面声明，定位稳定源节点或 UI 元素。包含目标资源的角色/舞台/页面等资源库通过原生依赖父边查找；不会仅因两个资源恰好同名就判定相同。结果区分直接使用与“使用包含目标的资源库”，后者不保证路线实际显示某张立绘差分。动态脚本仍需结合附加打包集合和扩展实现检查。

定位优先使用原生资产身份，随后校验节点或控件仍存在；已改变或删除的位置要求重新查找。UI 定位与画布/元素树使用引擎同一份文档限定选择，删除元素后安全回退，Undo 仍恢复原身份。

源范围覆盖 PNG/JPEG、WAV、TTF/OTF、VN 原生资产，以及该游戏原生闭包中其他已知路径。`~`、隐藏和重解析子树排除在普通项目清理候选外；插件依赖只读列出。这个范围不等同于引擎所有未知导入器。

“当前游戏未引用”只表示选定游戏的有效显式闭包没有该原生身份。其他游戏、启动场景、动态脚本或未声明打包资源仍可能使用它，不能据此删除。原生预检有错误时不判定未引用；资源导入身份不可用时显示“无法判断”。扫描期间改变的文件丢弃哈希，并要求重查。

重复组表示大小与 SHA-256 均相同的未变化源文件；原生身份、导入设置和故事用途仍可能不同。源字节数也不是最终 Player 包体积。

## 记录资源授权

在“VN 资源授权记录”创建 `.ivnlicenses`，选择资源后“记录所选资源”。填写作者、来源、许可名称、已确认的分发权限、署名要求、署名/许可正文和修改情况。结构合法但尚未填完的记录可保存；审计会提示缺项。

目录是普通原生创作资产，资源引用、保存、Undo/Redo 和重载沿用引擎机制。记录使用资源持久身份，保留 Missing 引用；不能用同一目录给同一资产保存两条相互冲突的当前记录。

回到资源审计，选择“使用所选授权目录”，或直接“创建并使用授权目录”。审计读取该共享文档的当前草稿。结果中可将资产加入当前目录，再到授权面板补充，保存后重新审计。

授权目录属于 Editor 创作数据，不能加入 Player 动态打包集合。它记录作者提供的信息，不自动验证许可真实性、条款适用性或最终成品是否携带全部要求的文件。插件内置只读资源应结合其随附许可和第三方声明核对。

## 导出报告

“保存报告与署名草稿”写入项目的 `artifacts/Publishing`：Markdown 包含原生引用、重复组、无法检查项和记录缺口；`-Notices.txt` 保留已记录的署名正文，供作者复核并纳入游戏发布流程。不会修改引擎导出清单或自动改写游戏内容。

本功能通过正式脚本编译和真实公开宿主资产/History 测试，包含文件变更检测及取消后句柄释放。没有 GUI、规模或成品分发验收；最新完整回归与定向测试分开记录。
