# 发布前检查

先保存章节与资源文档，再在 File Browser 选择游戏的 `.ivnproject`，打开「VN 发布检查」并运行检查。它复用游戏 Importer 的校验，并列出完整系统页面、Shader 契约、翻译审核问题和原生资产引用闭包。

资源闭包由引擎序列化服务收集，不扫描文件夹建立资产数据库。每项包含稳定资产身份、原生路径、直接引用来源与属性数据字节数；属性字节数不是包体积，最终体积以引擎构建报告为准。引用 `~Samples` 或其他 `~` 子树会阻止内容检查通过，因为这些目录不进入 Player。

扩展按字符串或运行结果选择资源时，在「VN 游戏设置」中将资源加入「动态打包集合」。这些资源保存为普通原生资产引用，参与依赖收集与游戏构建指纹。移除集合条目不会删除原资源。

内容没有错误后，可以打开引擎既有的 `Export as Game`。在引擎窗口中选择向导生成的启动 Scene 和 Windows x64，再执行引擎构建。按钮通过公开的 `export/game` 编辑器动作调用，不维护第二个打包器；当前宿主没有可用动作时会禁用并显示原因。

报告明确保留尚未验证的宿主要求。当前 Runtime 根序列化入口与自动扩展发现入口尚未公开，独立 Player 的无代码存档接入仍有缺口；扩展元数据也不能证明运行实现已经注册。打开导出窗口、内容检查通过或插件编译通过，都不等于完整 Windows 游戏已经验收。

可将检查报告保存到工程 `artifacts/Publishing`。本批次没有实际打开导出窗口、构建并游玩 Windows 游戏。
