# 页面、主题与剧情边界

在节点或剧本编辑器的「游戏系统 → 页面与主题」添加指令，使用同一份参数表单。可用动作如下。

| 动作 | 参数与行为 |
|---|---|
| 打开页面 | 选择游戏已关联的页面角色。先提交当前动作，再暂停在下一条指令之前；关闭页面、返回阅读后才继续 |
| 切换主题 | 选择游戏已关联的主题资源 ID；空值使用页面自身样式。不中断剧情，主题参与存档和回滚 |
| 返回标题 | 暂停当前剧情的下一条指令，转到标题。新游戏会创建新的剧情会话状态 |
| 创建命名检查点 | 填写非空名称；记录下一条指令之前的完整逻辑与演出状态，可从绑定列表或公开会话方法恢复 |
| 保存到自动槽 | 在独立自动槽策略中保存刚提交的剧情边界，与「遇到选项自动保存」设置独立 |
| 设置回滚屏障 | 填写原因，禁止回滚到本屏障之前；普通读档和开始新游戏仍遵循各自的明确行为 |

系统指令不在并行演出分支内执行，避免同时争用页面焦点、主题和持久化边界。编译与发布检查会定位非法分支、未关联页面和缺失主题。

## 自定义页面

在界面设计器创建页面并保存，然后在「VN 游戏设置」中填入自定义页面角色并关联所选页面。角色使用字母、数字、点、短横线或下划线。剧情指令可以打开它；页面按钮使用 `back` 或 `resume` 返回。界面元素可以绑定已声明变量，用于简单的无代码交互。

从页面返回的同一次确认不会继续跳过下一句对白。页面打开期间，后续变量赋值也不会提前执行。保存该状态时，使用中立的 `Suspended` 游标表示已提交动作之后的继续位置，读档不会再打开同一个页面或再次执行自动保存。

## 检查点与回滚

命名检查点与对白、选项检查点共用会话的有界回滚日志。`checkpoints` 列表暴露本次会话仍保留的名称；按钮使用 `checkpoint.rollback`，参数绑定 `item.id`。`NovelSession.RollbackToCheckpoint` 提供相同操作。

普通回滚跳过非交互命名边界，避免反复回到同一句话之前形成回滚陷阱。恢复后删除旧未来，过期或屏障之前的名称不再可选。普通读档会清理读档前的回滚日志；它不会把旧会话的检查点名称伪装成仍可恢复。

`history.hasBarrier` 和 `history.barrierReason` 可用于提示不可跨越的边界。已读、收藏解锁与全局变量不随回滚撤销。

## 自动保存与预览

显式自动保存需要宿主提供原生持久化服务。缺少服务时产生可定位错误，不把没有写入的数据标为成功。自动保存的原生 IO 失败通过保存服务的错误状态报告，保留上一个有效数据包。

正式 `NovelGameView` 在每次会话更新和输入后立即观察保存边界。高级宿主必须保持同样的所有权顺序；若自行推进会话越过尚未观察的自动保存边界，将收到错误，不会拿后来的状态冒充该保存点。

编辑器实际预览可使用原生 codec 与每个预览独立的临时内存存储，测试保存、读取和自动槽；结束预览即丢弃，不读取或覆盖玩家文件。独立 Player 的默认 codec 接入仍受当前正式 Runtime API 缺口限制，不能把编辑器可用的原生序列化能力视为已导出到 Runtime。

上述边界实现参考了 [Ren’Py 关于检查点与回滚的交互约束](https://www.renpy.org/doc/html/save_load_rollback.html)，具体状态与 API 是本插件自己的契约。此批次正在进行逻辑验证，未做 GUI 或实机验收。
