## 已确认的引擎边界

具体能力需求和取舍见 [原生运行时存档入口](Decisions/0001-RuntimePersistenceBoundary.md) 和 [正式宿主能力缺口](Decisions/0002-FormalHostCapabilityGaps.md)。它们不是已存在的引擎 API，也不表示生产 Runtime 存档已经接通。

- 通过独立工程的正式裁剪引用编译已确认：`SerializationRegistry` 仅导出到 Editor scope。Runtime 脚本无法创建根序列化操作；`SerializationReader`/`SerializationWriter` 的构造不公开。报告在 `artifacts/RuntimeSerializationProbe.txt`，可用 `Tools/Probe-RuntimeSerialization.ps1` 重现。需要引擎提供会话所有的 Runtime 序列化入口或等价的受控保存服务；本插件没有修改引擎，也没有增加 JSON/手写二进制旁路。
- 当前 `EditorAssets.Save` 会先成功构建导入产物再提交源，因此无效图草稿可以继续在文档中保留，但不能保存为无效创作源。引擎宿主拥有能够独立保存草稿的 AssetSourceStore，它尚未向脚本导出。当前文件冲突检查只覆盖保存前已发生的外部变更，未完成并发替换矩阵。
- 当前正式类型 API 仅导出 `StableTypeIdAttribute`，没有计划假设的 Runtime `TypeCache`/`TypeRegistry`。不能扫描 DLL 或反射穿透替代官方扩展发现；扩展发现能力仍需公开契约支持。
- 当前正式视口输入没有输入法组合态和手柄数据。UI 域可测试 composing 阶段禁止快捷键，宿主适配不能凭空补出该状态。截图回读类型已导出，插件已实现准确帧捕获、分离渲染/回读资源、异步提交与 PNG 缩略图链；逻辑与原生 RenderGraph 测试通过，GPU 回读尚无本批实机验收。
