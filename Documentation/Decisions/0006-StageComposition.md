# 舞台局部图像处理与合成边界

舞台与角色部位共用 VN 领域的 `StageSurface`。它只声明可序列化的归一化源区域、局部保留区域、混合与遮罩通道；不复制引擎矩形、纹理对象、资产身份或 GPU 状态。提取帧及渲染几何继续使用引擎 `Rect`。

枢轴属于 `StageTransform`，单位是本地像素，变换为“减去枢轴 → 缩放 → 旋转 → 移至放置点”。保留区域改变提取的几何及 UV，不改变声明尺寸、呼吸锚点或时间线目标。表情图像与序列帧继续应用同一部位的声明。

遮罩沿整个未裁剪的本地几何取样，先裁剪再提取；它与源图的图集区域相互独立。状态保存原生纹理 GUID，运行提取借用同一资源闭包的规范纹理，不序列化资源实例。语言资源映射同时覆盖当前/先前画面的源图与遮罩。

普通 Normal 图层使用原有直接绘制。遮罩与 Add/Multiply 触发现有图像合成图，先绘制源，再求遮罩，再将结果合成到已画背景。UI 上层不参与舞台图层混合。针对组的转场形成隔离组；组内混合不会越过该转场组的边界影响其他层。

合成公式参考 [W3C Compositing and Blending Level 1](https://www.w3.org/TR/compositing-1/) 的简单透明合成、Lighter 与 Multiply。Add 采用相加预乘颜色/覆盖度并截断；Multiply 使用保留双方未覆盖区域的预乘展开。实现复用现有两图后处理材质，不新增后端或功能插件。48 个特殊层的显式预算限制递归图与中间图像数量；超限拒绝候选，不依赖显卡耗尽后才失败。

新增模型字段后，旧的本仓库受控内置资产会因原生必需字段缺失而拒绝导入。处理方式是从原始声明经现有宿主序列化与 Importer 重建：保留 `.imeta` 身份、备份原源文件、刷新六舞台/两角色/五教学图。没有给生产格式增加旧 reader、兼容 alias 或迁移版本。

验证分别记录正式编译、原生资源/History 往返、纯渲染计划、UV 顶点、候选拒绝及离线 Shader。它们不代表 GPU、滤波边缘、实际颜色或 GUI 验收通过。
