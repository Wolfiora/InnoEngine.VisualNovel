# 调试来源与图中观察

执行位置来自生产 `StoryMachine.debugLocation` 和同一 `StoryDebugger`，使用原始章节/节点身份。并行暂停时优先使用调试器停止的任务位置，普通阅读使用当前交互任务。图中显示已应用到运行会话的断点；条件断点通过只读 `conditional` 属性识别，避免每帧复制条件树。显示标记保留作者的原生选择，居中操作复用现有 GraphCanvasState。

调试来源查询由 `PreviewSourceNavigator` 承担。它只检查明确游戏中的原生章节引用，以及启动局部预览时捕获的原始来源路径；不把当前活动文档当成故事身份，不扫描所有文件。未保存章节身份来自已有共享文档。匹配必须唯一，节点必须仍存在，插件只读来源需要先创建项目副本。

预检查返回现有 `StoryDocumentSnapshot`，查询不打开文档、不改变选择或写入源。UI 随后通过同一 StoryDocumentsModule 打开来源，再检查中立快照指纹，最后发布文档限定的节点选择。失败恢复原活动文档并保留预览；如外部变化发生在检查和打开之间，可能留下额外的未修改文档标签，但不会选择错误节点或覆盖源文件。公开宿主没有原子的“按预期修订打开”操作，这里不作该承诺。

来源已变化的预览要重新运行后再进行此定位。执行轨迹、任务位置、断点/单步和当前指令共用同一来源入口。局部来源路径在预览成功发布时捕获，停止时释放；不会把未知同名章节当作替代来源。

预览准备进度直接显示英文文案；带作者值的消息使用不变区域格式化。源路径和章节 ID 保留原值。诊断显示不改变剧情、存档或重载快照。
